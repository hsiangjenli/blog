## [^ospo]: What is an Open Source Program Office (OSPO)?

A unit dedicated to developing, managing, and promoting open source strategies. Its role is not limited to “using open source software”; it enables an organization to participate in the open source ecosystem systematically and strategically.

## [^ospo-core]: What are the core responsibilities of an OSPO?

https://ospoglossary.todogroup.org/ospo-definition/

| Area of Work                 | Details                                      |
| ---------------------------- | -------------------------------------------- |
| Open Source Governance       | Establish policies for using, reviewing, and contributing to open source software |
| License Compliance           | Manage licensing risks involving MIT, Apache 2.0, GPL, and others |
| Software Supply Chain Security | Promote SBOM, SCA, and open source component risk management |
| Open Source Contribution     | Establish processes for employees to submit PRs and report Issues |
| Open Source Strategy         | Decide which technologies are worth investing in, contributing to, or open sourcing |
| Community Engagement         | Participate in foundations, technical communities, and open source events |

## [^ospo-value]: What is the most important value of an OSPO?

It can be divided into three stages:

|          1          |          2          |         3         |
| :------------------: | :------------------: | :----------------: |
|  **Consume**  | **Contribute** |   **Lead**   |
| Use open source safely and in compliance |  Contribute to existing open source projects  | Lead projects and nurture communities |

It is not just about managing “which open source software the company uses,” but about considering how to make open source a long-term technical capability, competitive advantage, and external collaboration resource for the enterprise.
